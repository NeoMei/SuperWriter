# SuperWriter macOS / Windows 兼容性

## 范围

本次基于 `73f1966`（SuperWriter 0.2.1）改造本插件的安装、协作状态、配图处理、产物验收及使用说明。WPSComposer 的操作系统适配、COM/JSAPI 后端和 Office 环境由其独立项目负责；本仓库不审查或改动其实现。

写作阶段、逐对象明确确认、revision 冲突检查、批准内容 SHA-256 和真实 DOCX/PDF 验收规则保持原有语义。内容编码和换行变化仍属于字节变化，不通过重新计算历史批准摘要来接受变化。

## 平台接口

- 安装和安装验证由 Python 入口执行，Bash 与 PowerShell 仅作启动包装；Windows 不要求 Git Bash。安装验证入口从仓库运行；客户工作目录使用已安装 skill 中的协作及产物验收入口。
- WPSComposer 引用外部安装源，避免将部分运行时复制为不完整的独立安装；自身安装失败时恢复已有宿主内容和路由。
- 状态写入使用当前操作系统的进程间文件锁，继续保证同一 revision 的竞争提交最多一个成功；异常退出后由系统释放锁。
- 配图渲染、图片解码、色彩处理与 PDF 元数据检查使用跨平台依赖，缺失依赖或损坏输入仍返回失败。
- 项目根参数接受本机路径，持久化对象路径使用 `/` 相对路径。仓库 `.gitattributes` 固定文本 LF，冻结旧版流程文件和内容快照保持原摘要。

## SVG 字体差异

重新渲染 SVG 时优先执行完整像素比较。仅当完整比较失败时，对可解析的简单文字布局尝试有边界的文字区域比较：文字区域最多覆盖图像的 35%，区域外沿用原像素差异阈值，双方文字区域都必须存在对应填色的可见像素。无法安全解析的布局仍拒绝并说明原因。

此检查容许操作系统字体度量差异，不等同于逐字 OCR。SVG 标签、结构及文件摘要仍独立核对；审定 PNG 摘要及 DOCX/PDF 中嵌图的完整像素比较继续执行。不要依靠重新渲染后的文字外观替代用户对图像的确认。

## 验证方法

1. 原生 Python 完整回归覆盖状态模型、持久化、网页审阅、图片及 PDF 正反例。
2. 在一次性用户目录完成真实安装、重复安装、镜像核对和回滚注入；从客户目录调用安装后的 CLI 并启动 HTTP 审阅服务。
3. 隔离 Python 环境安装声明依赖，避免仅因开发机器已有工具而通过。
4. GitHub Actions 在 `macos-latest` 与 `windows-latest` 分别运行 Python 3.10、3.13 的相同回归套件。CI 使用已有 WPS 输出夹具检查本插件验收能力，不启动或验证 WPSComposer 后端。
5. `core.autocrlf=true` 检出检验覆盖冻结旧版文件和内容快照。

已完成 `core.autocrlf=true` 的临时检出检查：四个冻结 legacy-v1 文件摘要及 19 个内容快照字节完全一致。未修改的既有 v2 完整交付项目临时副本通过验收，安装后 CLI 与真实 HTTP 服务烟测通过。完整产物验收 shell 套件已通过；Python 3.10 的一轮完整回归通过 234 项（跳过 1 项 Windows 专属测试）。最终候选在 macOS / Python 3.13 上运行 239 项测试，通过 237 项，跳过 2 项 Windows 原生目录联接测试。原生双平台 CI 结果待分支运行后补充。

浅色文字缺失、索引 PNG 透明度、无效 ICC、窄字符编码和目录别名均有拒绝/等价性回归。目录联接通过 Win32 API 创建，不经命令解释器；重装保留外部联接，不递归复制其目标。安装父目录解析到 HOME 外或两个宿主解析到同一目录时，在写入前拒绝。

测试中的偏好与批准均为合成测试数据，不代表真实客户确认。CI 使用现有 WPS 产物验证 SuperWriter 的读取与验收；不启动 WPSComposer，不代表其 Windows 导出已经验收。
