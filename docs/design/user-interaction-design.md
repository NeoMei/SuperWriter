# SuperWriter v2 用户交互设计

## 目标

交互服务于具体写作取舍，并把每次决定绑定到可验证的对象版本。系统先消化当前客户材料，展示理解、矛盾、推荐方案与理由；只问一个会改变写法的问题。材料中已有答案不重复询问。

## 状态与证据

- 偏好点击、默认选择、沉默和机器核查只记录偏好或检查结果，不是批准。
- approach、outline、每个 chapter、figure_set 和 manuscript 都需要当前版本的明确用户批准。
- 修改意见产生 `changes_requested`，修订形成新 version 和 SHA-256，再提交审阅。
- 中断后从状态库恢复。内容漂移、上游修改或无效依赖会令对象失效，旧证据不能跨版本使用。
- 用户只确认迁移本身时，旧产物登记为 draft；不导入旧阶段号或聊天推测为批准。

## 七阶段交互

| 阶段 | 展示内容 | 交互与停止条件 |
| --- | --- | --- |
| intake | 需求摘要、评分点覆盖、已有材料、缺口和推荐访谈重点 | 吸收已有答案；记录偏好和材料状态；机器检查完成后继续 |
| approach | 完整写作方案、依据、风险、缺口处理与推荐主线 | 聚焦一个取舍；修订循环；用户明确批准当前方案后停止等待并推进 |
| outline | 完整章节结构、“要求→章节→依据”、每章目标和拟配图 | 修订循环；用户明确批准当前大纲后推进 |
| chapters | 当前章完整正文、依据、自查与待判断项 | 按大纲逐章；当前章批准后才起草下一章；首章校准风格 |
| illustrations | 完整配图集、每图图题与插入位置，或无图理由 | 修改循环；用户明确批准当前 figure_set 后推进 |
| manuscript | 完整合稿、矩阵覆盖、术语/编号/引用核查 | 修改循环；用户明确批准当前合稿后推进 |
| delivery | WPS 实际输出、验收结果；存在 layout 时展示实际版式预览 | layout 仅按需审阅；机器验收后 agent 记录 verified |

## 材料交互

材料要分别记录建议来源与取得方式、`proposed/acquired`、`unverified/verified`。只有 `acquired + verified` 能支持事实。关键材料未就绪时，系统给出推荐取得路径或缩小结论、删除内容、补证、明确限制等处理方案；替代处理必须写入并批准 approach，且精确匹配受影响章节。指定某联系人只是材料来源信息，除非用户明确授权，否则不向外发送消息。

## 配图集格式

审阅页从当前 figure_set 内容快照读取严格声明：

```markdown
## figure-01
图题: 数据交换总体架构
插入位置: 第二章“接口边界”段后
```

存储文件名、章节依赖和周边文字不能替代图题或插入位置。缺失或格式错误显示“未声明”。

## 恢复与界面

CLI 和可选 localhost 审阅页共享同一状态、身份与 revision 检查。网页不可用时使用项目内事件文件和 CLI，不降低确认要求。恢复时先显示当前对象、内容摘要、依赖、确认是否有效和下一动作，再继续当前修订或审阅循环。
