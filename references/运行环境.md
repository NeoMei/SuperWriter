# 持久 Python 运行环境

SuperWriter 的完整渲染和交付验收要求 Python 3.10 或更新版本及 `requirements.txt` 中的依赖。系统 Python 3.9 可以启动 `runtime.py` 的检查与引导，但不能作为实际工作环境。入口只使用标准库，不替换系统 Python，也不需要手动激活虚拟环境。

`setup` 是唯一安装依赖的命令。它用指定 Python 创建持久 venv，执行 `pip install -r requirements.txt`、`pip check` 和实际导入检查。`status` 与每次 `run` 都验证 Python 版本、依赖版本约束、递归依赖和选中的 extras（包括 DOCX/PDF），并导入主要渲染/验收模块；失败时提示显式运行 `setup`，绝不静默联网安装。检查不等于最终文档验收。

默认环境位置：

| 系统 | 默认目录 |
| --- | --- |
| macOS | `~/Library/Application Support/SuperWriter/runtime-v1` |
| Windows | `%LOCALAPPDATA%\SuperWriter\runtime-v1` |
| Linux | `$XDG_DATA_HOME/SuperWriter/runtime-v1`，未设置时使用 `~/.local/share/SuperWriter/runtime-v1` |

可以在子命令前用 `--runtime-dir` 指定单独目录；不要放在 `/tmp`、技能目录或仓库内。`--skill-root` 选择本次执行的技能版本，其 `requirements.txt` 和 `scripts/` 必须存在。默认选择入口脚本所在技能/仓库根目录。

## macOS

以下命令从 SuperWriter 仓库根目录执行。`setup --python` 应使用本机已有的 Python 3.10+；这里的路径仅为示例，按实际安装修改。

```sh
python3 scripts/runtime.py setup --python /opt/homebrew/bin/python3.12
python3 scripts/runtime.py status
python3 scripts/runtime.py run collaboration_state.py -- --help
python3 scripts/runtime.py run render_svg.py -- --help
python3 scripts/runtime.py run verify_acceptance.py -- /absolute/path/to/project
python3 scripts/runtime.py run verify.py
```

执行已安装技能而非源码时，显式选择根目录；入口仍可来自仓库，因此无需先覆盖已有技能：

```sh
python3 scripts/runtime.py --skill-root "$HOME/.agents/skills/superwriter" status
python3 scripts/runtime.py --skill-root "$HOME/.agents/skills/superwriter" run collaboration_state.py -- --help
```

## Windows PowerShell

从仓库根目录执行，Python 安装路径按本机情况填写。参数含空格时保留引号。

```powershell
py -3 scripts/runtime.py setup --python 'C:\Python312\python.exe'
py -3 scripts/runtime.py status
py -3 scripts/runtime.py --skill-root "$env:USERPROFILE\.agents\skills\superwriter" run render_svg.py -- --help
py -3 scripts/runtime.py run verify_acceptance.py -- 'C:\Work\Project'
py -3 scripts/runtime.py run verify.py
```

无需激活 venv。`run` 保留当前工作目录，原样转发脚本参数和退出码，并将持久环境的命令目录置于子进程 PATH 首位，确保 MarkItDown 等命令来自已核验环境；脚本名仅允许 `collaboration_state.py`、`render_svg.py`、`verify_acceptance.py`、`verify.py`。`verify.py` 属于源码仓库，检查安装镜像和依赖契约；已安装技能通常不包含它。运行仓库验证时必须选择仓库根目录。未更新安装镜像期间，源码与镜像不一致会如实报错。

## 修复和并发

环境目录带 SuperWriter 所有权标记；已有但未标记的目录一律拒绝接管，文件不会删除。换用一个新的 `--runtime-dir` 即可。环境目录不能是符号链接。中断安装保留当前目录和诊断信息，再次显式 `setup` 可补装缺失依赖；若虚拟环境解释器本身损坏或版本过旧，选用新目录重建，不自动删除旧目录。

同一环境的 `setup`、`status`、`run` 通过相邻的 `.lock` 目录串行化，避免安装与执行并发。锁存在时命令立即报错。正常退出自动解锁；进程异常终止后，先确认没有其他运行入口进程，再手动移除该空锁目录。入口不会按超时强行夺锁。

依赖按所选版本的 `requirements.txt` 范围安装，并非冻结版本锁文件。源码验证通过、镜像更新、真实 WPS 导出和交付文件验收是各自独立的证据。
