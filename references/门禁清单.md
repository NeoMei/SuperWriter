# 七阶段核查清单（protocol v2）

`references/阶段契约.json` 定义推进语义。`explicit` 表示当前对象必须有真实用户确认；`conditional` 表示仅在存在需判断的 layout 对象时增加版式确认。机器核查通过不能代替确认。

## intake

- [ ] 招标文件、评分表、硬性要求与交付边界已解析
- [ ] 应答矩阵覆盖每个主评分点，主责章节唯一
- [ ] 已展示需求摘要、矛盾、材料缺口及推荐方案
- [ ] 材料取得路径、取得状态和核验状态分别登记

## approach [review=explicit]

- [ ] 方案包含目标、响应主线、文风、篇幅、材料使用、缺口处理和交付标准
- [ ] 关键材料已取得并核验，或方案绑定明确的替代处理
- [ ] 当前版本、SHA-256 与用户证据已记录为批准

## outline [review=explicit]

- [ ] 每章含目标、观点、评分点映射、证据、缺口、篇幅和拟配图
- [ ] 大纲依赖当前已批准方案
- [ ] 当前版本、SHA-256 与用户证据已记录为批准
- [ ] 修订时仅按同一次用户批准事件保留身份、字节和原确认仍有效的未改章节

## chapters [review=explicit, repeat=true]

- [ ] 按大纲顺序完成当前章，评分点和材料可追溯
- [ ] 所需关键材料为 `acquired + verified`，或匹配已批准替代决定
- [ ] 当前章完整正文已展示并完成自查
- [ ] 当前章版本、SHA-256 与用户证据已记录为批准后才进入下一章

## illustrations [review=explicit]

- [ ] 配图集登记图 ID、图题和插入位置，且图文依赖当前章节
- [ ] 每个 Markdown 声明使用 `## <figure-id>`、`图题:`、`插入位置:`
- [ ] 无图时已登记并展示 `mode=none` 的明确决定
- [ ] figure_set 当前版本已由用户明确批准

## manuscript [review=explicit]

- [ ] 所有章节与配图集均为当前有效批准版本
- [ ] 术语、编号、引用与风格一致，应答矩阵覆盖完整
- [ ] 完整合稿已展示，当前版本、SHA-256 与用户证据已记录为批准

## delivery [review=conditional]

- [ ] delivery 报告与验收清单分开，均绑定当前合稿
- [ ] 如存在 layout 对象，已展示实际 WPS 预览并取得用户对当前版式的确认
- [ ] DOCX/PDF 来自当前合稿，实际文件验收已通过
- [ ] agent 通道已用实际合稿、DOCX、PDF 摘要记录 `record_delivery`
- [ ] 清单已刷新到记录后的 revision，并再次验证；delivery 状态为 `verified`
